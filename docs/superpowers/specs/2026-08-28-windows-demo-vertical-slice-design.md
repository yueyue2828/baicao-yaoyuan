# 《百草药园》Windows Demo 纵向切片设计

**状态：** 已确认设计，实施路线与第一阶段计划已建立
**日期：** 2026-08-28  
**上位文档：** `2026-08-28-chinese-herbal-idle-rpg-gdd.md`

## 1. 目标

首个公开版本是一个可独立安装、完全离线运行的 Windows 纵向切片。它用 30～45 分钟验证以下核心承诺：

1. 玩家完成“种植 → 收获 → 获得随机母株 → 鉴定词条 → 配置 BD → 自动战斗 → 获得新资源 → 回到种植”的完整循环；
2. 母株具备类似刷宝游戏装备的品质、词条、数值范围和百分位追求；
3. 至少两套 BD 能以不同机制击败区域 Boss，第三套在其他挑战中明显占优；
4. 战斗全自动，玩家的策略集中在战前构筑、自动规则和战后复盘；
5. 中药文化内容与幻想游戏规则明确分栏，不把游戏效果表述为现实疗效。

通关后显示结算，但不结束存档。玩家可以继续刷取母株、优化 BD，并刷新最佳战斗记录。

## 2. 已锁定决策

| 项目 | 决策 |
|---|---|
| 首版平台 | Windows 10/11 安装包 |
| 公开 Web 版 | 不提供；浏览器仅用于开发调试 |
| 移动端 | 不进入首版范围 |
| 技术栈 | Vue 3 + TypeScript + PixiJS + Tauri 2 |
| 战斗操作 | 全自动，玩家不在战斗中手动释放技能 |
| 通关后 | 保留进度并开放自由刷取 |
| 离线成长 | 包含，单次最多累计 8 小时 |
| 美术制作 | 分层绘卷 + 代码 UI |
| 联网能力 | 不需要账号、服务器或联网权限 |

## 3. Demo 内容范围

### 3.1 包含

- 1 个地区；
- 2 块药田、2 个田地等级；
- 甘草、黄芪、生姜、肉桂、当归、川芎 6 种药材；
- 6 档母株品质、约 20 条普通词条、3 条传奇异变；
- 主角药师与 2 名随机弟子；
- 6 个方剂槽与自动释放条件；
- 补益护盾、温热爆发、活血速攻 3 套基础 BD；
- 6 场普通战斗、2 场精英战斗、1 个区域 Boss；
- 4 名普通患者与 1 个疑难医案；
- 本草图鉴的 6 份完整条目；
- 本地存档、三份轮换备份、导出与导入；
- Windows 安装程序和分辨率设置。

### 3.2 不包含

- 完整五阶田地、五个地区和正式主线；
- 完整育种、复杂嫁接和弟子出师；
- 六种药性全部开放；
- 24 节气、药铺经营、无限秘境、赛季或联网功能；
- Android 安装包或公开 Web 试玩版；
- 现实剂量、处方推荐或自行用药建议。

## 4. 玩家流程

| 时间 | 阶段 | 新理解 | 关键结果 |
|---|---|---|---|
| 0～5 分钟 | 首次种植 | 播种、生长、收获 | 获得第一批普通药材 |
| 5～10 分钟 | 首次灵光 | 收获可能出现永久母株 | 获得第一株随机母株 |
| 10～15 分钟 | 鉴定词条 | 品质不是唯一标准，词条组合与百分位同样重要 | 比较并装备母株 |
| 15～22 分钟 | 组建 BD | 母株、弟子、方剂和自动规则共同构成玩法 | 保存首个队伍预设 |
| 22～35 分钟 | 三类挑战 | 不同挑战检验不同 BD | 获得升级、图鉴和新种源 |
| 35～45 分钟 | 区域 Boss | 通过战斗报告调整构筑 | 通关并进入自由刷取 |

普通失败不扣除母株或不可再生资源。失败后保留战前状态，允许立即更换母株、弟子、方剂或自动释放规则。

## 5. 核心界面

### 5.1 药田主界面

- 展示两块田的作物、成长阶段、剩余时间和可收获状态；
- 支持播种、收获、田地升级和进入离线结算；
- 收获时区分普通药材与“灵光母株”，稀有掉落使用独立动画、音效和印章反馈；
- 作物成熟后永久保持待收获状态，不会枯萎。

### 5.2 本草收藏

- 支持鉴定、比较、装备、锁定、提炼和收藏；
- 母株卡片显示品质、实际数值、可能范围、当前百分位和 BD 适配提示；
- 品质同时通过颜色、印章、边框纹样、音效和粒子表达，不能只依赖颜色；
- 被锁定的母株不能提炼或被任何批量操作选中。

### 5.3 队伍与 BD

- 队伍由主角药师和两名弟子组成；
- 主角装备 6 株母株，队伍共享 6 个方剂槽；
- 自动规则支持冷却完成、生命比例、敌人状态层数、药气阈值和仅对精英/Boss 使用；
- 支持三个完整预设，预设同时保存母株、弟子、方剂、阵位和自动规则。

### 5.4 自动战斗与报告

- 战斗实时自动进行，普通战斗目标时长 30～60 秒，Boss 目标时长 90～180 秒；
- 支持 1×、2×、4×速度；
- 报告显示主要伤害与治疗来源、方剂释放次数、药气溢出或短缺、状态覆盖率、首名阵亡角色及原因；
- 每次失败提供一条基于数据的调整建议，不直接给出唯一答案。

## 6. 总体架构

### 6.1 分层

```text
Vue 3 应用界面                 PixiJS 游戏表现
药田 / 收藏 / BD / 设置         自动战斗 / 掉落 / 轻动画
              \                 /
               纯 TypeScript 游戏核心
       种植 / 离线 / 母株 / 词条 / 战斗 / 任务 / 经济
                 |          |          |
             JSON 配置   Pinia 会话状态   Tauri 本地服务
                                        存档 / 备份 / 窗口 / 安装包
```

Vue 与 PixiJS 只提交命令并展示状态，不自行计算规则。种植、离线结算、掉落和战斗必须能在没有界面的环境中运行。

### 6.2 模块边界

| 模块 | 职责 | 依赖 |
|---|---|---|
| `domain/farming` | 播种、成长、成熟、收获、田地升级 | 配置、时钟、随机源 |
| `domain/mother-plant` | 品质、词条、异变、鉴定、比较、锁定与提炼 | 配置、随机源 |
| `domain/build` | 队伍、母株、方剂、自动规则和预设验证 | 母株与弟子数据 |
| `domain/combat` | 战斗模拟、状态、药气、报告与确定性复现 | 构筑快照、关卡配置、随机源 |
| `domain/clinic` | 普通坐诊、疑难医案、证据与评分 | 方剂、患者配置 |
| `application` | 用例编排、命令、事件和状态投影 | 所有领域模块 |
| `ui-vue` | 管理型界面和响应式布局 | 应用层接口 |
| `render-pixi` | 战斗、掉落和场景动画 | 应用层只读状态与事件 |
| `infra-tauri` | 文件、窗口、备份、导入导出和安装包 | Tauri API |

模块对外暴露类型化接口。领域模块不引用 Vue、PixiJS、Pinia 或 Tauri。

### 6.3 确定性

游戏核心使用可注入的时钟和随机源。存档保存随机状态；相同存档、队伍、关卡和随机状态必须得到相同结果。战斗报告与批量平衡模拟使用同一个战斗实现，避免测试逻辑与正式逻辑分叉。

## 7. 数据流

一次收获流程如下：

```text
玩家点击收获
→ 应用层创建 Harvest 命令
→ farming 校验成熟状态
→ 随机源决定普通药材或灵光母株
→ mother-plant 生成品质、词条和异变
→ 领域事件写入当前会话
→ Vue/PixiJS 根据事件播放结算
→ Tauri 原子保存新状态
```

一次战斗流程如下：

```text
玩家选择关卡与 BD 预设
→ application 生成不可变战斗快照
→ combat 在固定步长中模拟全部行动
→ PixiJS 消费战斗事件流进行表现
→ combat 输出结果与战斗报告
→ 胜利时 application 发放奖励
→ Tauri 原子保存；失败时恢复战前快照
```

## 8. 美术与显示

### 8.1 分层绘卷

素材分为背景、角色、母株、田块、特效和 UI 六层。首版使用以下动画预算：

- 角色：待机、普通行动、受击三组轻动画；
- 药田：播种、生长、成熟三个状态；
- 母株：普通展示、稀有灵光、传奇异变三个强度层级；
- 战斗：方剂以墨迹、药香、叶片、印章和矿物色光效表达；
- 关键稀有掉落优先获得动画与声音预算，普通操作保持克制。

### 8.2 分辨率策略

- Vue 管理界面采用响应式重排，不采用无限拉伸；
- PixiJS 使用 1280×720 安全区；4:3 裁切装饰边缘，21:9 扩展两侧背景；
- 支持最低 1024×640 窗口以及 4K 显示器；
- UI 独立缩放 80%～200%，并适配 Windows 100%、125%、150%、200% 系统缩放；
- 关键按钮支持键盘焦点，品质和状态同时使用文字、形状与颜色。

## 9. 存档与离线结算

### 9.1 存档内容

存档至少包含：

- `schemaVersion`、`gameVersion`、`savedAt`；
- 随机源状态；
- 药田、作物与生产任务；
- 库存、母株、锁定状态与图鉴；
- 弟子、队伍和三个 BD 预设；
- 关卡、患者、任务与通关记录；
- 音频、显示、窗口与可访问性设置；
- 校验值。

### 9.2 原子写入

1. 写入临时文件；
2. 回读并校验结构和校验值；
3. 将旧正式存档轮换为最近三份备份；
4. 替换正式存档；
5. 再次读取关键字段确认。

触发时机包括收获、鉴定、提炼、队伍变更、战斗结算、坐诊结算、每 60 秒以及正常关闭。

### 9.3 离线算法

```text
离线秒数 = clamp(当前时间 - savedAt, 0, 8 小时)
```

离线期间只推进作物生长和已经明确委派的生产任务，不自动重复播种、不自动刷副本。成熟作物保持待收获。若系统时间倒退，本次离线收益为零并显示说明，不处罚玩家。

## 10. 异常恢复

- 正式存档损坏时，按新到旧顺序尝试三份备份；
- 所有备份均失败时显示恢复界面，允许导出诊断信息或开始新存档，不能静默覆盖旧数据；
- 战斗模拟异常时恢复战前快照，不扣方剂、药气或挑战次数；
- 配置文件在启动时进行结构、ID、引用、数值范围和文化资料状态校验；
- 发现无效配置时显示可理解的错误页，不用空数据继续运行；
- 存档升级通过逐版本迁移函数完成，迁移前保留原文件备份。

## 11. 中药文化与安全

- 每条文化资料明确标记“传统记载”“现代规范与安全”或“游戏设定”；
- 现实来源字段、保护状态、毒性提示和游戏效果字段分别存储；
- 未完成来源审核的文化条目不得进入公开构建；
- 方剂战斗技能明确标注为“游戏原创试作方”，不得伪装成现实处方；
- 不提供现实剂量、疗程或自行用药建议；
- 乌头、附子等有风险药材必须展示安全说明；
- 保护动物或敏感来源不得作为鼓励现实采集的普通素材。

## 12. 测试策略

### 12.1 规则测试

使用 Vitest 覆盖：

- 固定种子下的母株品质、词条数量和合法词条池；
- 同一种子、队伍与关卡的战斗可复现性；
- 提炼和洗练的资源守恒；
- 方剂优先级、冷却、药气和自动条件；
- 8 小时离线上限与系统时间倒退；
- 存档写入、备份恢复和逐版本迁移。

### 12.2 批量平衡模拟

使用正式领域逻辑批量模拟：

- 1 小时内首株佳品概率；
- 3 小时内首株保底仙品；
- 30～45 分钟通关资源分布；
- 三套基础 BD 的成型时间与挑战优势；
- 无限刷钱、负库存、资源闭环和无上限状态叠加。

### 12.3 界面与安装测试

- 使用组件测试覆盖药田、鉴定、BD、战斗报告和恢复界面；
- 使用 Playwright 覆盖完整纵向切片流程和目标分辨率；
- 使用 Windows 安装包验证安装、启动、卸载、无网络运行、中文路径、中文用户名和旧存档迁移；
- 测试 Windows 10/11 及 100%、125%、150%、200% 系统缩放。

## 13. 验收标准

1. 新玩家在 10 分钟内理解“母株相当于永久装备”；
2. 30～45 分钟内可以击败区域 Boss；
3. 至少两套 BD 能采用不同机制通关；
4. 战败后玩家能根据报告做出一次有意义的构筑调整；
5. 通关后可继续刷取并优化母株；
6. 目标分辨率下不存在关键内容截断、遮挡或不可滚动区域；
7. 存档损坏测试能够恢复备份且不丢失所有进度；
8. 离线结算不超过 8 小时，不自动重复播种或刷副本；
9. 安装包无需 Node.js、Rust、浏览器或数据库即可运行；
10. 完全断网时所有 Demo 功能正常。

## 14. 实施边界

首轮实施只构建上述纵向切片，不并行开发正式版五阶内容、Android 适配、联网服务、完整节气系统或全套逐帧动画。后续扩展必须复用已验证的领域接口、存档版本机制和配置校验规则。
